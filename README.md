## 1. 서비스 소개

사용자가 대상 연령, 수업 시간, 수업 주제, 음악 개념, 활동 유형, 음악교육 접근법 등의 조건을 입력하면 AI가 수업안을 생성합니다. 교사가 수업안을 처음부터 구성하는 시간을 줄이고 다양한 음악 활동 아이디어를 쉽게 얻도록 제작했습니다.

### 타겟 사용자

- 유치원 교사
- 어린이집 교사
- 유아음악 강사
- 유아 대상 음악수업을 준비하는 교육자

## 2. 서비스 목적과 차별점

유아음악 수업은 연령과 발달 수준뿐 아니라 수업 시간, 음악 개념, 활동 방법, 악기와 교구, 음악교육 접근법을 함께 고려해야 합니다. 이 서비스는 단순한 질문에 답하는 범용 AI가 아니라 교사가 실제로 수업을 준비하는 순서를 입력 화면과 결과에 반영했습니다.

| 비교 항목 | 과제의 기본 기능을 쉽게 설명하면 | 이 프로젝트에서 더 확장한 내용 |
|---|---|---|
| 입력 방법 | 사용자가 AI에 전달할 내용을 입력할 수 있어야 합니다. | 질문 작성이 어려운 사람도 사용할 수 있도록 연령·시간·주제·음악 개념·활동·교수법·클래식·교구를 순서대로 선택하게 만들었습니다. |
| AI 결과 | AI가 입력 내용을 처리해 결과를 화면에 보여줘야 합니다. | 수업 목표·준비물·도입·전개·마무리·교사 팁·확장 활동을 구분한 한 차시 수업안으로 만들었습니다. |
| 유아음악 전문성 | 기본 과제는 특정 교육 분야의 교수법까지 요구하지 않습니다. | 유아음악 강사 경험을 바탕으로 오르프·달크로즈·유리드믹스와 실제 수업 흐름을 반영했습니다. |
| 다시 만들기 | 기본 생성 기능은 입력한 조건으로 결과를 한 번 만드는 것입니다. | 같은 조건으로 새 수업안 만들기와 조건을 변경해 새로 만들기를 구분했습니다. |

- **조건 바꿔서 새 수업안 만들기:** 기존 입력 중 필요한 조건을 수정한 뒤 새 수업안을 생성합니다.

## 9. AI 동작 흐름

1. `index.html`이 수업 조건 입력 화면을 보여줍니다.
2. `js/script.js`가 사용자의 입력값을 수집합니다.
3. `fetch('/api/generate')`가 JSON 입력값을 백엔드에 전달합니다.
4. `api/generate.py`가 필수 입력을 검증하고 프롬프트를 구성합니다.
5. Python 서버리스 함수가 OpenAI API를 호출합니다.
6. 생성 결과를 JSON으로 프론트엔드에 반환합니다.
7. JavaScript가 수업안 항목별 HTML을 만들고 화면에 표시합니다.

### 대표 프롬프트 구성 예시

```text
5세 유아를 대상으로 25분 동안 진행할 유아음악 수업안을 작성해 주세요.
주제는 '봄 숲에서 만난 사자'이며 빠르기와 셈여림을 다룹니다.
신체 표현과 감상 활동을 포함하고 유리드믹스 접근법을 반영해 주세요.
리본막대와 북을 사용하며 목표·준비물·도입·전개·마무리·교사 팁·확장 활동을 구분해 주세요.
```

## 10. fetch 요청과 상태 처리

프론트엔드는 JSON 형식으로 서버리스 함수에 요청합니다.

```javascript
fetch("/api/generate", {
  method: "POST",
  headers: {
    "Content-Type": "application/json"
  },
  body: JSON.stringify(formData)
})
```

- 필수 입력이 없으면 AI 호출 전에 누락 항목을 안내합니다.
- 생성 중에는 버튼 문구와 진행 안내를 변경해 중복 요청을 막습니다.
- 성공하면 수업안 결과를 출력하고 Fade-up 효과를 적용합니다.
- 서버 오류나 응답 지연이 발생하면 실패 상태로 전환하고 재시도 방법을 안내합니다.
- 프론트엔드는 최대 240초까지 기다리고 제한 시간을 넘으면 요청을 중단합니다.

## 11. 실패 처리와 실제 안내

| 상황 | 실제 안내 또는 화면 처리 | 사용자 행동 |
|---|---|---|
| 필수 입력 누락 | `수업안을 생성하지 못했습니다. 수업 시간을 선택해 주세요.` | 누락 항목을 선택한 뒤 다시 생성합니다. |
| 생성 중 | `AI 수업안 생성 중...`, `AI가 수업안을 설계하고 있습니다.` | 현재 처리가 진행 중임을 확인합니다. |
| API·서버 오류 | 수업안을 생성하지 못했다는 오류 메시지를 표시합니다. | 잠시 후 다시 시도합니다. |
| 응답 지연 | 현재 처리 상태를 단계별 문구로 표시합니다. | 생성이 끝날 때까지 진행 상태를 확인합니다. |
| 240초 초과 | 제한 시간 초과와 재시도 안내를 표시합니다. | 다시 생성 버튼을 누릅니다. |

## 12. 긴 입력 테스트

평가 항목의 긴 입력 처리 여부를 확인하기 위해 추가 요청란에 약 250자 이상의 상세한 수업 조건을 입력했습니다.

### 문제 발생 시 확인 순서

1. Vercel 프로젝트의 `Logs`에서 `/api/generate` 요청과 상태 코드를 확인합니다.
2. Chrome에서 `F12 → Console`을 열어 JavaScript 오류를 확인합니다.
3. `Network`에서 `/api/generate` 요청·응답 상태와 시간을 확인합니다.
4. 문제가 있는 코드를 수정하고 Git commit과 push를 진행합니다.
5. Vercel `Deployments`에서 자동 재배포가 `Ready`인지 확인합니다.
6. 실제 배포 사이트에서 같은 조건으로 다시 테스트합니다.

## 14. 실행 방법과 환경변수

### 프로젝트 실행 준비

```bash
pip install -r requirements.txt
```

OpenAI API 사용에는 다음 환경변수가 필요합니다.

```text
OPENAI_API_KEY
```

실제 API Key는 소스 코드에 작성하지 않고 Vercel 프로젝트의 Environment Variables에 등록합니다. 프론트엔드는 키를 직접 사용하지 않고 `/api/generate`만 호출하며 실제 OpenAI 요청은 `api/generate.py`가 처리합니다.

### API Key 노출 점검 방법

```bash
git grep -n "sk-"
git grep -n "OPENAI_API_KEY"
```

- `sk-`로 시작하는 실제 키가 검색되면 안 됩니다.
- `OPENAI_API_KEY`는 환경변수 이름이나 문서 설명으로만 나타나야 합니다.
- 키가 노출되면 기존 키를 폐기하고 새 키를 발급합니다.
- 새 키는 필요한 프로젝트에만 등록하며 GitHub에는 저장하지 않습니다.

## 15. Vercel Serverless Functions

이 프로젝트는 별도 서버를 계속 실행하는 대신 `api/generate.py`를 Vercel Serverless Function으로 사용합니다. 요청이 들어올 때 Python 함수가 실행되어 입력을 검사하고 OpenAI API 결과를 반환합니다. 이를 통해 API Key를 브라우저에 노출하지 않으면서 AI 기능을 사용할 수 있습니다.

## 16. 보너스 기능

## 17. 개발 및 개선 과정

실제 Vercel 배포 환경에서 다음 문제를 반복 테스트하며 수정했습니다.

- GitHub push 후 Vercel 자동 재배포 확인

## 18. 응답 지연 개선 방안

현재는 생성 중 안내와 최대 240초 제한으로 사용자가 진행 상태를 알 수 있게 했습니다. 아래 기능은 현재 적용했다고 주장하는 것이 아니라 실제 운영 시 속도·품질·비용을 비교해 적용할 수 있는 향후 개선 방안입니다.

| 개선 방법 | 기대 효과 | 주의점 |
|---|---|---|
| 같은 요청 결과 캐시 | 동일 조건의 반복 요청 시간을 줄일 수 있습니다. | 오래된 결과를 갱신하는 기준이 필요합니다. |
| 경량 AI 모델 사용 | 생성 속도와 비용을 줄일 수 있습니다. | 수업안의 구체성과 품질을 함께 비교해야 합니다. |
| 지나치게 긴 입력 요약 | AI에 전달하는 문장 길이를 줄일 수 있습니다. | 중요한 수업 조건이 빠지지 않아야 합니다. |
| 결과 분량 제한 | 응답 생성 시간을 줄일 수 있습니다. | 수업안 필수 항목은 유지해야 합니다. |

## 19. 프레임워크 변경 시 예상 영향

현재 프로젝트는 HTML·CSS·JavaScript와 Python 서버리스 함수로 구성했습니다. React·Vue 같은 프레임워크로 변경하면 다음 영향이 예상됩니다.

| 변경 영향 | 내용 | 대비 방법 |
|---|---|---|
| 파일 구조 | 화면이 여러 컴포넌트로 나뉩니다. | 홈·입력·결과·오류 화면을 역할별로 분리합니다. |
| 빌드 과정 | 프레임워크 빌드 명령과 출력 폴더 설정이 필요합니다. | Vercel Build Command와 Output Directory를 확인합니다. |
| 환경변수 | 프론트와 서버에서 환경변수를 읽는 방식이 달라질 수 있습니다. | API Key는 계속 서버에서만 사용합니다. |
| API 연결 | `/api/generate` 경로나 설정이 달라질 수 있습니다. | 기존 요청·응답 형식을 유지하며 연결 테스트를 진행합니다. |
| 배포 설정 | 프레임워크에 맞는 Vercel 설정이 필요합니다. | 별도 브랜치에서 확인한 뒤 `main`에 반영합니다. |
